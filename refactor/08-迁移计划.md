# 08 · 迁移计划

在 `refactor` 目标结构下分 7 个阶段实施；每阶段可独立验收、可回滚（旧 `src/`
在 Phase 6 切流前始终可运行）。原型样例已验证的基线能力（房间页面、Orval 请求、
非法参数 400、同端口 Socket.IO ack）作为各阶段的冒烟标准。

## Phase 0 · 骨架与依赖定稿（0.5 天）

- 新建 `app/ server/ shared/ scripts/` 目录与 `react-router.config.ts`、`vite.config.ts`、
  两份 tsconfig。
- `package.json`：按 README 依赖定稿表安装；`engines.node >= 22.22`。
- `server/index.ts` 最小版：Fastify + 适配器 + `GET /api/health`，Socket.IO attach 空实现。
- **验收**：`npm run dev` 单端口打开首页；`curl /api/health` 200；socket 握手可连（空房间处理）。

## Phase 1 · 契约与代码生成链路（0.5 天）

- `shared/message.ts`、`shared/events.ts`（04 §1）。
- `server/app.ts` 组装 zod type provider、`@fastify/swagger`、error handler。
- `scripts/export-openapi.ts` + `orval.config.ts`，跑通 `npm run codegen`。
- **验收**：`/documentation` 可见全部（空）路径；`app/api` 有生成物；故意传非法
  query 返回 400（样例行为复刻）。

## Phase 2 · 服务层（1 天）

- `config.ts`（env zod，含 v2 的 TURN/P2P 项）+ `redis.ts` + `room.ts`（注册/secret/outbox）
  + `statistics.ts` + `minio.ts` + `ice.ts` + `cleanup.ts`（06 全量），含旧 STRING 键一次性清理脚本。
- **验收**：jest（ioredis-mock）覆盖 createRoom 重试/secret 哈希、verifyJoin 三态、
  outbox 前缀校验、ice 凭证 HMAC、sweep 判定、sanitizeName 边界；`MINIO_*` 假配置下签名函数可注入测试。

## Phase 3 · HTTP API（1 天）

- `routes/rooms|uploads|statistics|health|webrtc` 按 03 契约实现（schema + handler → services）。
- **验收**：`app.inject` 用例全绿；对真实 Redis/MinIO 手动过 A1–A4、A8；403/404 分支齐；
  `npm run codegen` 后 diff 为空。

## Phase 4 · 信令 + P2P 传输层（2 天，v2 重写）

- 服务端：`realtime/index.ts`（握手 zod/secret/顶号、CORS/pingInterval env）+
  `signaling.ts`（`rtc:signal` 定向转发）+ `room-handlers.ts`（roster/进出场/
  outbox 推送/relay 降级 ack，04 §4）。
- 客户端：`app/lib/p2p/peer-machine.ts`（Perfect Negotiation）+ `frames.ts`（编解码）
  + `transfer.ts`（分块/背压/sha256）。
- **验收**：jest——信令集成（双 client：secret 错拒连、顶号、to 不在房拒转）；
  p2p 单测（mock RTC：glare 分支、文件回路校验）。手工——两标签页 localhost 直连
  （host candidate 即通）互发文本/文件；关 TURN env 验证 8s 落 relay；
  断线重连 mesh 自动重建。清扫只出现在定时器日志。

## Phase 5 · 前端迁移（3–4 天，最大工作量）

按 05 逐页迁移，顺序：layout/路由骨架 → 入口页（secret 入 fragment）→
传输层接线（`use-room`：socket+peer-machine+IndexedDB 历史）→ 房间页
（列表/输入/在线状态条 → 文件 P2P/MinIO 双路由 → 拖拽/粘贴 → 分享/OutboxPanel）→ 数据页。
antd-mobile 每替换一页即删对应 less。

- **验收**：对照 01 §2 行为清单 + 05 §8 的 v2 清单逐项打勾；重点回归
  P2P 文件进度、离线回执领取、relay 角标、旧链接 `/room?roomId=` 重定向（403 引导新建）。

## Phase 6 · 切流与清理（0.5–1 天）

- `npm run build` 全链路（build/client + dist/server），`npm start` 生产模式验收同 Phase 5 清单。
- docker-compose 升级 node:22、**部署 coturn**（TURN_HOST/TURN_SECRET、UDP 端口段
  放通，07 §5）、env 注入密钥（**先轮换泄漏的 AK/SK**）、宿主 3004 映射不变。
- 旧 Redis STRING 房间键一次性清理脚本（06 §3）。
- 删除：`src/`、`typings/`、`dist/`、`gulpfile.js`、`nodemon.json`、`ecosystem.config.js`
  旧字段、`config.json`、ts-brpc 相关（`_rpc_gen_meta_.json`、`ts-brpc.json`）、
  `.drone.yml` 中旧构建命令更新。
- README 重写为新的 dev/build/deploy 说明。

## Phase 7 · 后续增强（不阻塞上线，按需排期）

秒传（A4 加 sha256 + statObject 检查）、限流（`@fastify/rate-limit` 挂 A1/A4/A8）、
`@socket.io/redis-adapter` 多实例、**relay 模式端到端加密**（libsodium，10 §14）、
多设备历史 E2EE 同步评估（10 §14）、连接方式埋点（10 §12）、
房间页过期倒计时展示（A2 的 ttlSeconds）、音视频通话（信令已就绪，独立立项）、
`/data` 权限控制（现状裸奔，建议先加 Basic Auth 或移出公开路由）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| Redis 旧 STRING 房间键与新 HASH 结构冲突 | 不做双结构共存：上线前一次性清理脚本删除旧键（06 §3，聊天历史在 P2P 下无消费方） |
| HeroUI 3.x 无 antd-mobile 的个别组件（ImageViewer 等） | 自研小组件清单已在 05 §3 列明，工作量可控 |
| 适配器/RR8 新版本的 API 漂移 | 依赖定稿版本锁死；升级属 Phase 7 评估项 |
| 上传 URL 协议策略变化导致 https 页面 Mixed Content | 保留 `auto` 为过渡默认（等价现状）；确认反代带 TLS 后再切 `https` |
| **P2P 连接成功率不达预期（对称 NAT/UDP 封锁）** | 降级链三级（P2P→TURN→relay）全实现；上线埋点统计各模式占比，决定补 TURN 还是放宽 relay（10 §12/§14） |
| TURN 被滥用产生带宽账单 | A8 需房间 secret + 凭证 12h 过期 + username 内嵌 room/peer 可审计 + coturn 侧配额（07 §5） |
| 浏览器 WebRTC 实现差异（SCTP 分片上限、背压事件） | 帧 ≤64KB 安全基线 + `bufferedAmountLow` 有 polyfill 分支 + 真机矩阵覆盖 Chrome/Safari/Firefox |
| 本地 IndexedDB 历史丢失（清浏览器数据） | 产品语义明示（10 §1）；导出房间记录为 JSON 的轻量补救按钮 |
