# 01 · 功能提炼（现状盘点）

从当前代码（Koa + ts-brpc + Socket.IO + Redis + MinIO + React 17 + antd-mobile）逐文件
提炼出的功能清单。这是重构后必须保持等价的行为基线。

## 1. 产品形态

SEND 是一个**匿名房间分享工具**：创建一个 4 位数字房间号，把链接/二维码发给对方，
双方在房间里互发文本、链接和文件。文件由浏览器直传 MinIO，消息历史存 Redis，
实时通道走 Socket.IO。

## 2. 页面功能

### 2.1 入口页 `/`（`src/client/pages/entry`）

| 功能 | 现状实现 |
|---|---|
| 创建房间 | 点「创建房间」→ 调 `Room.join()`（不带参数）→ 服务端生成 4 位数字号 → 跳转 `/room?roomId=xxxx` |
| 输入房间号进入 | 点「进入房间」展开输入框，**输满 4 位自动跳转**（延迟 200ms 防看错），失焦收起 |
| 演示视频 | 非移动端 UA 时右侧播放 `minio.8and1.cn/static/send/example.mp4`（loop、muted、poster） |
| 布局 | HomeLayout：Header（SEND 标题，点击回首页）+ Footer |

### 2.2 房间页 `/room?roomId=`（`src/client/pages/room`）

**进入校验**
- 无 `roomId` 或校验失败 → Toast 提示 → 跳回首页。
- 调 `Room.join(roomId)` 确认房间存在且未过期。

**聊天列表**（`list.tsx` + `useSocket.tsx` + `chatList`/`bubble`/`msgType`）
- 连接状态机：`connecting / connected / disconnect`；空列表时显示「暂无分享」或 connecting。
- 收到 `ROOM_JOINED` 事件即拿到**服务端历史消息**并初始化列表。
- 文本消息：http(s) 开头渲染为外链。
- 文件消息：按扩展名渲染 `react-file-icon` 图标 + 文件名 + 人类可读大小，点击新窗口打开。
- 图片消息（apng/avif/gif/jpeg/webp/png/svg/jpg）：缩略图 + antd-mobile `ImageViewer` 大图预览。
- 气泡右侧状态：上传中显示进度环（percent%）、失败显示红叉、成功不显示；气泡上方显示时间。
- 复制按钮：文本复制、图片写入剪贴板（`ClipboardItem` + canvas 转 png）、文件复制下载链接
  （http 页面降级为 `document.execCommand` 方案，`utils/copy.ts`）。

**发送**（`chatInput` + `list.tsx onSendChange`）
- 回车键全局监听发送文本；有内容时出现「发送」按钮。
- 「+」按钮选择**多文件**依次发送。
- **粘贴图片**：`paste` 事件捕获剪贴板图片 → 预览确认对话框 → 确认后作为文件发送。
- **拖拽**（`upload/cover.tsx`）：拖入文件直接上传；拖入图片 URL 文本（匹配 `http.*png|jpe?g|gif`）
  直接作为「已完成的文件消息」发送；拖入文件夹提示不支持；拖拽悬停显示遮罩提示「可以松开了哦」。

**文件上传流程**（客户端编排，服务端只签名）
1. 本地先插入 `status:'uploading', percent:0` 的消息（乐观上屏）。
2. 文件 >1MB 时计算 MD5（spark-md5 分块 2MB）——**当前计算了但未参与秒传**，为遗留半成品。
3. 调 `Upload.getUploadAction({ fileName, roomid })` 拿预签名 PUT/GET URL（7 天有效）。
4. `XMLHttpRequest PUT` 直传 MinIO，`upload.onprogress` 驱动进度环。
5. 成功后 `socket.sendMsg(fileMessage)`，失败标记 `rejected`。

**实时语义**
- 自己发的消息只本地回显，**不收回声**（服务端广播时跳过发送者）。
- 发送走 ack 回调：`{ success, message }`，失败把气泡标红。
- 对方收到文件消息时直接置 100%/resolved。

**分享面板**（`shared.tsx`）
- 当前 URL 生成二维码（`qrcode.toDataURL` 300×300，手机端扫码进房）。
- 「链接」「房间号」两个只读复制输入框。

### 2.3 数据页 `/data`（`src/client/pages/data`）

- 拉取活跃房间号列表与用户列表（`Statistics.getCurrentRoomts` / `getUserList`）。
- 房间号可点击跳转进房。当前只渲染了 rooms，users 取了未展示。

## 3. HTTP API 清单（现状：ts-brpc，POST `/api/<Service>/<method>`）

| 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `Room.join` | `roomId?: string` | `{ roomId }` | 不带参=创建（随机 4 位数字，循环直到不冲突）；带参=校验存在/未过期 |
| `Room.getRoomMessageHistory` | `roomId: string` | `Message[]` | **有 bug**：内部调 `getRoom()` 忘传 roomId，实际不可用（历史由 socket ROOM_JOINED 下发） |
| `Upload.getUploadAction` | `{ roomid?, fileName }` | `{ upload, download }` | MinIO 预签名 PUT + GET，Key=`${roomid‖referer中的roomid‖uuid}/${fileName}`，7 天过期；referer 是 https 时剥掉 URL 的协议头 |
| `Statistics.getCurrentRoomts` | 无 | `string[]` | Redis Set `statistics-rooms` |
| `Statistics.getUserList` | 无 | `string[]` | Redis Set `statistics-users` |
| `Ping.ping` | 无 | 空 | 存活探测（无路由级实现，走 RPC） |

**响应信封**（`common/response.ts`）：`{ code: number, message: string, status: 'ok'|'error', data?: T }`，
错误也是 HTTP 200 + `status:'error'`。

**消息模型**（`lib/interface.ts`）：
`Message { id: string; type: 'text'|'file'; text?; url?; file?: { name, size }; time?; sendBy? }`

## 4. Socket.IO 清单（`server/ws/socketIO.ts`，与 HTTP 同端口）

| 项 | 现状 |
|---|---|
| 连接 | `io(url, { transports:['websocket'], query:{ roomId, username } })`，username 来自 cookie |
| 握手处理 | 按 query.roomId 记录 `statistics-rooms`；房间存在则 `socket.join(roomId)` 并 `emit ROOM_JOINED(历史消息)` |
| `MSG_SEND` | 入参 `(message, callback)`；服务端补 `time=Date.now()`、`sendBy=username`、剥 url 协议头；`pushMessage` 落 Redis；向房间内**其他人**广播 `MSG_RECEIVE`；回调 ack |
| `MSG_RECEIVE` | 服务端→其他成员：`(message)` |
| `ROOM_JOINED` | 服务端→新成员：`(historyMsgs: Message[])` |
| 断开 | `socket.leave`；当全局 socket 数 <3 时，遍历 `statistics-rooms` 清理不存在/空消息的房间（`removeRoomKey + removeRoom`） |
| 服务器配置 | CORS origin 硬编码列表；`pingInterval: 3500` |

事件名常量来自 `SOCKET_EVENT_MAP = arrayToMap(['ROOM_JOINED','MSG_SEND','MSG_RECEIVE'])`，
类型 `SocketHandler` 前后端共用 —— 这是 `shared/events.ts` 的前身。

## 5. 服务与存储

### 5.1 Redis（`server/service/room.ts` / `statistics.ts`）

| 键 | 类型 | 内容 | TTL |
|---|---|---|---|
| `room-{roomId}` | string | 消息数组 JSON（整读整写，无并发保护） | 常量名 `sevenDay` 实为 **30 天**（每次 push 后重续） |
| `statistics-rooms` | set | 用过的房间号 | 无（靠断线清扫逻辑回收） |
| `statistics-users` | set | 用户名 | 无（`recordUser` 被注释，实际不写入） |

### 5.2 MinIO（`server/controller/upload.ts`）

- Endpoint `minio.8and1.cn:80`（http），bucket / AK / SK 来自 `server/config.json`。
- 只做**预签名**，服务器不过文件流；`presignedPutObject` + `presignedGetObject` 成对返回。
- 存在性检查（秒传用）代码被注释，未启用。

### 5.3 配置与基础设施

- `server/config.ts`：读 `config.json` 合并默认值（redis host/port、minio bucket/endpoint/ak/sk）。
- 日志：log4js 双通道（out/err 按日期文件，`logs/` 目录）。
- 静态托管：生产由 Koa `koa-static` 托管 `dist/client` + history fallback（`/api` 白名单）。
- 构建：client=vite；server=ts-brpc 生成元数据 + gulp(tsc)；dev=nodemon；prod=pm2 cluster /
  docker-compose（redis:6 + node:20 容器，宿主 3004→容器 3000）。
- 测试：jest + supertest，覆盖 room/upload/statistics service（依赖真实 Redis）。

## 6. 技术债与需在重构中修正的问题

| # | 问题 | 出处 | 处理建议（详见各设计文档） |
|---|---|---|---|
| D1 | `getRoomMessageHistory` 忘传 roomId，接口不可用 | room.ts 控制器 | v2 口径关闭：服务端历史职责整体退役（P2P 不留痕），由 A3-outbox + 本地 IndexedDB 替代（10 §1/§3） |
| D2 | 创建房间 while 循环可能死循环、`randomWord` 用 `Math.round` 分布不均 | controller/room.ts、utils | 有界重试 + `crypto.randomInt` |
| D3 | 无请求校验、无 schema；错误全靠信封 `status:'error'` | 全部控制器 | Zod schema + 真实 HTTP 状态码（样例已验证 400） |
| D4 | 密钥进仓库（config.json）且 `outLogger.info(bossConfig)` 打印明文 AK/SK | upload.ts | 迁移到环境变量 + zod 校验，禁止打印 |
| D5 | `sevenDay` 常量命名与值（30 天）不符 | service/room.ts | 更名 `ROOM_TTL`，值可配置 |
| D6 | 整数组读改写存消息：并发丢消息、大房间全量读写 | service/room.ts | 方案里定为 Redis List（`RPUSH`/`LRANGE`），接口不变 |
| D7 | 断开清扫在每次 disconnect 全量 `fetchSockets` + 遍历房间 | socketIO.ts | 改为低频定时清扫任务 |
| D8 | 上传 Key 直接用原始 `fileName`（路径注入/重名覆盖风险）；roomid 从 referer 解析兜底很脆弱 | upload.ts | Key 加服务端随机前缀 + 文件名清洗；roomId 走 query/body 显式传 |
| D9 | `statistics-users` 只读不写（recordUser 被注释） | socketIO.ts | 恢复写入握手 |
| D10 | MD5 计算了但秒传未实现 | list.tsx | 作为可选增强，不进本期等价迁移 |
| D11 | React 17 + antd-mobile 5、全局回车监听（输入框回车也触发发送） | client | 随前端重写处理 |
| D12 | 协议剥离 `replace(/https?:/,'')` 散落在上传/消息两处 | upload.ts、socketIO.ts | 收敛到统一配置（公网 URL 基址），避免行为漂移 |
| D13 | 身份体系是死代码：`getCookie('username')` 被前后端到处读取，但**全仓库无任何写入点**，`sendBy` 实际恒为 undefined | useSocket.tsx、socketIO.ts | P2P 方案重设计：客户端生成 `peerId`（uuid，localStorage 持久），握手/历史/统计的唯一身份（10 §3） |
| D14 | 房间可进入性无鉴权：4 位数字仅 10⁴ 空间，任意活跃房间可被枚举闯入（旧架构丢消息，P2P 后威胁升级） | controller/room.ts | 创建房间签发邀请 secret（URL fragment 传递，服务端存哈希），HTTP + socket 双校验（10 §11） |

> 迁移验收以「第 2～5 节的行为」为准；第 6 节问题按对应设计文档逐条销账。
> **v2 修订**：§2.2 的「服务端历史消息」「服务器存消息」两项被 P2P 方案取代
> （历史改本地 IndexedDB，见 10 §1/§3），其余行为保持为验收基线。
