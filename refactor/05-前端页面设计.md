# 05 · 前端页面设计（React Router 8 + HeroUI 3.2.6）

## 1. 运行模式

- React Router 8 **framework mode**（Vite 插件），`react-router.config.ts` 设
  **`ssr: false`**：本项目是纯客户端交互应用（socket 驱动），与现状 CSR 行为等价，
  构建产物为 SPA shell + assets，由 Fastify 适配器托管（dev 经 Vite，prod 经
  `@fastify/static` + catch-all）。
- 样式：**Tailwind v4 + HeroUI 3.2.6**（`@heroui/react` + `@heroui/styles`），
  全面替换 antd-mobile 与 `*.module.less`。Vite 插件链：`@tailwindcss/vite` →
  `reactRouter()` → `fastifyReactRouterDev({ entry: './server/index.ts' })`。

## 2. 路由表与 URL 兼容

```ts
// app/routes.ts
export default [
  layout('routes/_layout.tsx', [
    index('routes/index.tsx'),                 // 入口页
    route('room/:roomId', 'routes/room.$roomId.tsx'),  // 房间页（路径参数）
    route('room', 'routes/room-legacy.tsx'),   // 兼容 /room?roomId= 旧链接 → 重定向
    route('data', 'routes/data.tsx'),          // 数据页
  ]),
]
```

| 项 | 决策 |
|---|---|
| 房间 URL | 新规范 `/room/{roomId}#s={secret}`（fragment 不入服务端日志；取代 `/room?roomId=`） |
| 旧链接兼容 | 旧格式 `/room?roomId=` 仍重定向到 `/room/{roomId}`；但**无 secret 的链接进不了 v2 房间**（403 → 引导对方新建，10 §1） |
| 生成分享链接 | 房间页二维码与复制框一律用新格式 `location.href` |
| `/data` | 保留，补显示 users（现状取而未渲） |

## 5. 传输状态机：`app/hooks/use-room.ts`（v2 重写）

取代旧 `useSocket.tsx`，把「信令通道（socket）」与「数据通道（WebRTC）」封装成一个状态机：

```ts
const {
  conn,          // 'connecting' | 'signaling' | 'p2p' | 'relay' | 'offline'
  peers,         // [{ peerId, name, transport: 'host'|'srflx'|'relay', dcOpen }]
  messages,      // UiMessage[]（IndexedDB 本地历史 + 实时增量 + 乐观上屏）
  outbox,        // 离线文件回执
  sendText, sendFile, retry,
} = useRoom(roomId, secret)
```

- **peerId**：`crypto.randomUUID()` 首次生成后 localStorage 持久（取代 D13 的死 cookie），
  socket auth 与 DC `hello` 帧都带它；UI 显示名可另存。
- socket 只处理：roster、进出场、`rtc:signal` 转发（喂给 `app/lib/p2p/peer-machine.ts`，
  Perfect Negotiation 模式）、outbox 推送、relay 降级。事件与 payload 类型来自 `shared/events.ts`。
- `peer-machine` 每个对端一个 RTCPeerConnection；ICE 清单来自 A8；dc open 超时 8s
  或失败 → `conn` 降级为 socket relay（10 §10）。
- reducer 动作：`roster/set`、`peer/join|leave`、`msg/append|patch`（按 id 幂等，与本地
  历史同键）、`outbox/add|remove`。
- 历史：进房先渲染 IndexedDB（`idb-history`），再叠实时增量——原「服务端 ROOM_JOINED
  下发历史」的验收项就此替换（10 §1）。「发送者不回声」由本地乐观上屏保证，不依赖服务端。

## 6. 文件发送编排（v2：P2P 优先，MinIO 兜底）

```
sendFile(file):
  1. id = crypto.randomUUID(); 乐观 append { status:'uploading', percent:0 }
  2. 路由决策：
     size ≤ P2P_FILE_LIMIT(32MB) 且存在 dcOpen 的对端 → 走 P2P：
       ctl:file-begin{id,name,size,mime,sha256} → 对端 file-ready →
       bin 通道 64KB 分块 + bufferedAmount 背压 → file-progress 校准 percent →
       两端各自写 IndexedDB（同 msgId 幂等）
     否则（>32MB / 对端离线 / relay 模式）→ MinIO 路径：
       postApiUploadsSign({roomId,fileName,size}) → xhr PUT（upload-put.ts）
       ├ 对端在线(relay)：sendViaSocket(msg 带 url) —— 现状语义
       └ 对端离线：PUT /api/rooms/:id/outbox{元数据+key} → 回执卡片「等待领取」
```

- 拖入图片 URL：跳过传输，直接 append 完成态（`url` 指向外链），经 ctl/relay 通知（同现状）。
- 发送失败（DC 断、校验不过、上传报错）统一标 `rejected`，气泡上给「重试」→
  重试时重新执行路由决策（对端可能已上线/离线）。
- `getFileMD5`（spark-md5）保留调用位但不再是主链路：sha256 由 `crypto.subtle`
  在分块时增量预算（P2P 路径）或上传前算好（MinIO 路径写入回执）。

## 7. API 调用

页面/组件一律 import `app/api`（orval 生成）：入口页用 `postApiRooms`（拿 roomId+secret），
房间页校验用 `getApiRoomsRoomId`（带 `x-room-secret` 头），ICE 用 `getApiWebrtcIceServers`，
上传签名用 `postApiUploadsSign`，回执用 outbox 两端点，数据页用 statistics 两函数。
不保留旧 `rpc.*`、`BaseUrl` 拼接逻辑；开发/生产同端口后 `baseUrl` 恒为 `/api`
（现状 dev 硬编码 `127.0.0.1:3000/api` 的问题一并消除）。

## 8. 验收对齐清单（前端侧）

创建/输入房间号进入、**secret 校验（403 引导新建）**、本地历史渲染、在线状态与
连接方式角标（P2P/TURN/relay）、文本+链接发送、**对方离线时文本禁发提示**、
P2P 文件传输（进度/校验/重试）、大文件与离线文件走 MinIO+回执领取、粘贴图片确认、
拖拽文件/图片URL、图片预览、三种复制、二维码与链接分享（含 #s=）、断线重连与
mesh 重建、`/data` 列表、移动端布局（HeroUI 响应式断点替代原 less 媒体查询）。
真机连接矩阵（10 §12）作为房间页验收的一部分，缺 TURN 环境的降级路径必须实测。
