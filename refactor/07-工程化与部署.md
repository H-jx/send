# 07 · 工程化与部署

## 1. 入口：`server/index.ts`（示意，非实现）

```ts
import { buildApp } from './app'
import { fastifyReactRouter } from '@mcansh/react-router-fastify'
import { attachSocket } from './realtime'
import { startCleanupTimer } from './services/cleanup'
import { env } from './config'
import { pathToFileURL } from 'node:url'
import type { ViteDevServer } from 'vite'

// 适配器约定：具名导出 createServer(vite?)，dev 由 fastifyReactRouterDev 调用
export async function createServer(vite?: ViteDevServer) {
  const app = await buildApp({ docs: env.NODE_ENV !== 'production' })

  await app.register(fastifyReactRouter, {
    devServer: vite,          // prod 时 import build/server + 托管 build/client
    staticOptions: { index: 'index.html' },
    assetCacheControl: 'public, max-age=31536000, immutable',
  })

  attachSocket(app.server)    // Socket.IO 与 Fastify 共用一个 http.Server
  if (!vite) startCleanupTimer()  // dev 插件复用工厂时避免定时器重复注册

  return app
}

// 仅生产/独立运行入口自行监听（dev 由 Vite 插件监听，避免双端口冲突）
if (import.meta.url === pathToFileURL(process.argv[1]).href) {
  const app = await createServer()
  await app.listen({ port: env.PORT, host: '0.0.0.0' })
}
```

要点：
- 适配器在 Fastify 上注册 `all /*` catch-all；`/api/*` 与 `/documentation*` 先注册，
  路由树按优先级匹配，互不影响（原型样例已验证同端口页面+API+socket 共存）。
- `attachSocket` 之前 Fastify 不 listen，`app.server` 已存在（Fastify 懒创建），
  engine.io 直接接管 upgrade。

## 2. 脚本编排（package.json，目标态）

```jsonc
{
  "engines": { "node": ">=22.22.0" },          // React Router 8 硬性要求
  "scripts": {
    "dev": "react-router dev",                 // Vite + fastifyReactRouterDev：单端口 3000
    "build:app": "react-router build",         // → build/client + build/server
    "build:server": "tsc -p tsconfig.server.json", // server/ + shared/ → dist/server
    "build": "npm run build:app && npm run build:server",
    "start": "cross-env NODE_ENV=production node dist/server/index.js",
    "openapi": "tsx scripts/export-openapi.ts",
    "codegen": "npm run openapi && orval --config scripts/orval.config.ts",
    "typecheck": "tsc -p tsconfig.json --noEmit",
    "lint": "eslint . --ext .ts,.tsx",
    "test": "jest",
    "docker:dev": "docker compose up -d redis"
  }
}
```

- dev 不再需要 `rpc:server` 代码生成步骤（ts-brpc 退役）；`nodemon`、`gulp`、
  `cross-env`（除 start 外）退役。
- `scripts/export-openapi.ts`：`const app = await buildApp({ docs: true })` →
  `fs.writeFileSync('openapi.json', app.swagger())`，全程不 listen。
- CI 顺序：`codegen` → `git diff --exit-code openapi.json app/api` → `typecheck` →
  `test` → `build`。

## 3. TypeScript 与 Vite

| 文件 | 用途 |
|---|---|
| `tsconfig.json` | 全项目 typecheck：`paths: { "@/*": ["./*"] }`（app/server/shared 通吃），`jsx: react-jsx`，module `nodenext` |
| `tsconfig.server.json` | 只编译 `server/ + shared/` → `dist/server`（客户端代码不进服务端产物） |
| `vite.config.ts` | 插件：`@tailwindcss/vite` → `reactRouter()` → `fastifyReactRouterDev({ entry: './server/index.ts', exportName: 'createServer' })`；`server/index.ts` 以**具名导出** `createServer(vite?)` 工厂供 dev 插件复用（适配器 README 约定）；独立生产入口见 §1 的 `import.meta.url` 守卫 |
| `react-router.config.ts` | `{ ssr: false }`；未来要 SEO 再开 prerender |

React Router 8 与 Node 22：Docker 基础镜像从 `node:20-alpine` 升到 `node:22-alpine`。

## 4. 日志 / CORS / 安全

| 项 | 方案 |
|---|---|
| 日志 | Fastify 内建 **pino**（dev：pino-pretty；prod：JSON 到 stdout，容器/pm2 收集），**移除 log4js 文件轮转**（现状 `logs/` 目录方案不再需要）；请求日志带 `requestId`（Fastify genReqId 用 `uuidv4`） |
| CORS | `@fastify/cors`，origin 白名单来自 `CORS_ORIGINS`；Socket.IO `cors.origin` 用同一份配置（两处读一个来源，替代现状硬编码数组） |
| Helmet | 可选 `@fastify/helmet`，本期不加（行为对齐优先），备注 |
| 限流 | `@fastify/rate-limit` 留给 Phase 7（非必须）：重点保护 `POST /api/rooms` 与 `POST /api/uploads/sign` |
| 密钥 | 全部 env（见 06 §1）；`config.json` 删除并轮换泄漏的 AK/SK |

## 5. 部署形态

一个进程一个端口，部署面比现状更小：

```
docker-compose.yml
  redis:  redis:7-alpine（或保持 6，行为无关）ports 27125:6379
  app:    node:24-alpine，command: npm start
          ports "3004:3000"（保持宿主机映射现状）
          env: REDIS_URL=redis://redis:6379, MINIO_* , CORS_ORIGINS,
               TURN_HOST/TURN_SECRET/STUN_URLS（v2，见下）
  turn:   coturn/coturn:latest（v2 新增，可选——不配则降级链变短）
          network_mode: host（UDP relay 端口段不适合 bridge 映射）
          配置：listening-port=443(udp) tls-listening-port=5349
                relay-ip-range=0.0.0.0/0, min/max-port=49160-49180
                use-static-auth-secret, realm, no-tcp（走 443 伪 TCP）
```

- 外网仍经现有反代（send.8and1.cn → 3004），需要反代转发 `Upgrade/Connection` 头
  （现状 Socket.IO websocket 已经如此，无新增要求）。
- **v2 网络要求（新增）**：coturn 需公网放通 UDP 443/5349 + relay 端口段
  49160–49180/udp；`TURN_HOST` 未部署时 A8 只下发 STUN——P2P 仍尽力打洞，
  失败落 relay 模式。TURN 流量是唯一新增运维成本项（10 §9）。
- pm2 备选：`ecosystem.config.js` 改 `script: dist/server/index.js`；
  **exec_mode 用 fork、instances 1**——Socket.IO 单进程内存适配器不能 cluster
  （现状名义 cluster 实跑 1 实例，行为不变）；若要多实例，须引入
  `@socket.io/redis-adapter`（备注，不在本期）。
- 构建产物：`build/`（React Router）+ `dist/server/`（tsc）；`.dockerignore/.gitignore`
  增加 `build/`、`dist/`，保留 `openapi.json`（进 git），忽略 `app/api/`（生成物）
  或反之——**方案取「app/api 进 git、CI 校验一致性」**，便于直接读代码评审前端调用。

## 8. 实施勘误（2026-11-20 实测记录）

| 设计稿假设 | 实测结果 | 落地处理 |
|---|---|---|
| 注册 `@fastify/cors` 做 CORS | @fastify/cors v11 会注册 `options('*')` 预检路由，与适配器 catch-all `all('*')` 冲突（"already declared for route '*'"） | **移除 @fastify/cors**。单端口架构下页面/API/socket 全同源，本就不需要 HTTP CORS；Socket.IO 跨域由 engine.io 响应头配置处理。未来真跨域用 onRequest hook |
| `ssr: false` 即可 | RR 8.5.2 下 ssr:false 默认触发 prerender，prerender 在 Node 环境执行页面代码导致超时 | `react-router.config.ts` 显式 `prerender: false`；深链/刷新由适配器 SPA fallback 服务（dev/prod 实测 200） |
| 浏览器 API 仅客户端调用 | prerender/SSR 构建仍会静态求值部分模块 | `isMobile()`、cookie 读取等全部加 `typeof window/navigator` 守卫 |
| tsconfig 只需 include `.react-router/types` | typegen 的 `+types/*.ts` 以 rootDirs 映射解析相对导入 | tsconfig 增加 `"rootDirs": [".react-router/types", "."]` |
| 本地测试用 MinIO 容器 | MinIO 开源镜像与二进制已官方归档下线（410/denied） | 本地验证改用 **SeaweedFS S3 网关**（真实校验 AWS4 SigV4，预签名 PUT/GET 实测 200）；生产仍对接 MinIO。兜底可用 `scripts/fake-s3.mjs`（不校验签名） |
| Orval fetch 客户端可区分 HTTP 错误 | 生成的 fetch 客户端对非 2xx 不抛错 | `app/api/index.ts` 封装层统一 `ApiError(statusCode)`；页面用 `instanceof ApiError + statusCode` 区分 400/404/413/502 |
| 适配器 `addContentTypeParser('*')` 仅作用自身 | 该 passthrough 解析器对全局生效 | 客户端 POST 一律显式 `Content-Type: application/json`；非 JSON 请求体按 400 拒绝（行为正确） |
