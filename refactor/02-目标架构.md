# 02 · 目标架构

## 1. 一句话架构

**一个仓库、一个 Node.js 进程、一个端口（3000）。Fastify 是服务入口，负责 `/api/*`、
请求校验和 OpenAPI；React Router 负责页面；Socket.IO 挂在同一个 HTTP server 上，
承担 WebRTC 信令、在线状态与降级中继；聊天数据面走浏览器间 WebRTC DataChannel（10）。**

```
浏览器
  │  :3000
  ▼
┌──────────────────────────────────────────────────────────┐
│ Node.js 进程（server/index.ts）                            │
│                                                          │
│  Fastify 5（HTTP 入口）                                   │
│   ├── /api/*            → server/routes/*（zod 校验）      │
│   │     rooms · uploads · statistics · health · webrtc      │
│   ├── @fastify/swagger  → /documentation + openapi 导出    │
│   └── @mcansh/react-router-fastify（catch-all 注册）       │
│         └── React Router 8 framework mode（app/ 页面）      │
│               生产模式同时用 @fastify/static 托管 build/client│
│                                                          │
│  http.Server（app.server，同一端口）                        │
│   └── Socket.IO（server/realtime，attach 到 app.server）    │
│         /socket.io/* 由 engine.io 先行拦截，其余请求交还     │
│         Fastify 路由，互不冲突                              │
│         职责＝信令搬运/在线名单/降级中继/回执推送（10）        │
│    （聊天文本与文件内容经 WebRTC DataChannel 浏览器间直传，   │
│      不进入本进程；大文件/离线例外走 MinIO，见下）            │
│                                                          │
│  server/services（业务层，routes 与 realtime 共用）          │
│   ├── room.ts        → Redis 注册/secret/outbox           │
│   ├── statistics.ts  → Redis 统计集合                      │
│   ├── ice.ts         → TURN 临时凭证签发                   │
│   ├── minio.ts       → 预签名 PUT/GET                      │
│   └── redis.ts       → ioredis 单例                        │
└──────────────────────────────────────────────────────────┘
          │                       │
       Redis 6+                MinIO
 （房间注册/回执/统计）     （大文件与离线回执的直传存储）
```

## 2. 关键决策与理由

| 决策 | 说明 |
|---|---|
| Fastify 为唯一入口 | 静态页面、API、文档都在同一个 Fastify 实例上；不再像现状那样 Koa + RPC 生成两套心智 |
| 页面用 React Router 8 framework mode | 由 `@mcansh/react-router-fastify@6.0.2` 适配：开发模式经 Vite 插件把 Fastify app 挂进 `react-router dev`（**开发也只有一个端口**）；生产模式 import `build/server/index.js` 并用 `@fastify/static` 托管 `build/client` |
| Socket.IO 不走 Fastify 路由 | `new io.Server(fastify.server, …)`：engine.io 在 HTTP server 层先匹配 `/socket.io/*`，非匹配请求交还 Fastify。信令通道与 `/api/*`、页面天然同端口、同域，无 CORS 问题 |
| **数据面 P2P（v2 修订）** | 文本与文件经 WebRTC DataChannel 端到端直传，服务器不中转不留痕；打不通依次降级 coturn 中继 / Socket.IO relay。完整设计见 10 |
| Zod schema = HTTP 契约唯一来源 | 路由注册时声明 `schema`（params/query/body/response），Fastify 自动校验（非法入参 400，样例已验证）；`@fastify/swagger` 从同一批 schema 生成 OpenAPI；orval 从 OpenAPI 生成前端 fetch 客户端。**前端不再手写请求函数** |
| 房间 API 与 Socket.IO 共用房间服务 | 注册、secret 校验、在线名单口径、文件回执（outbox）与过期清理只存在于 `server/services/room.ts`；HTTP 与信令两侧同一实现（v2：消息落库职责退役） |
| 浏览器继续直传 MinIO | 大文件（>32MB）、对端离线回执、URL 直贴三类场景仍走预签名 PUT/GET，文件不过 Node，保持现状带宽模型 |
| 实时事件类型放 `shared/events.ts` | 前后端 import 同一模块（现状 `lib/interface.ts` 的正名），事件名、payload、ack 形状只定义一次 |

## 3. 目录职责详解

```
send/
├── app/                        # React Router 8 应用（浏览器侧一切）
│   ├── root.tsx                # <html> 骨架、HeroUI/Tailwind 样式入口、Toast 容器
│   ├── routes.ts               # 路由表（createRoutes）
│   ├── routes/
│   │   ├── _layout.tsx         # Header/Footer 布局（原 homeLayout）
│   │   ├── index.tsx           # 入口页：创建/加入房间（原 entry）
│   │   ├── room.$roomId.tsx    # 房间页：聊天 + 上传 + 分享（原 room）
│   │   └── data.tsx            # 数据页（原 data）
│   ├── components/             # 会话气泡、消息渲染、输入区、拖拽层、二维码、复制框…
│   ├── hooks/
│   │   └── use-room.ts          # 传输状态机（p2p/relay/离线三态，原 useSocket.tsx）
│   ├── lib/
│   │   ├── p2p/                  # PeerConnection 机、帧编解码、文件分块传输（v2）
│   │   ├── idb-history.ts        # IndexedDB 本地聊天历史（v2）
│   │   └── (原有工具)            # XHR 直传、复制、文件大小/MD5
│   ├── api/                    # orval 生成物（只读，不手改），带 .gitignore 例外说明
│   └── styles/                 # Tailwind v4 入口 + 主题变量（HeroUI 3.2.6）
├── server/
│   ├── index.ts                # 创建 Fastify、注册插件/路由、挂 Socket.IO、listen
│   ├── app.ts                  # buildApp()：不 listen，供 dev 复用与 OpenAPI 导出、测试
│   ├── routes/                 # 每个资源一个文件，schema 与 handler 同处
│   │   ├── rooms.ts            # 注册/secret 校验/在线数/outbox（A1-A3）
│   │   ├── uploads.ts          # 预签名（A4）
│   │   ├── statistics.ts       # 房间/用户统计（A5-A6）
│   │   ├── health.ts           # GET /api/health（A7）
│   │   └── webrtc.ts           # GET ice-servers（A8，v2）
│   ├── services/               # 业务层（被 routes 与 realtime 共用）
│   │   ├── redis.ts
│   │   ├── room.ts             # 注册/secret/outbox/清扫
│   │   ├── statistics.ts
│   │   ├── ice.ts              # TURN 临时凭证 HMAC（v2）
│   │   └── minio.ts
│   ├── realtime/
│   │   ├── index.ts            # attachSocket(server)：握手校验、顶号
│   │   ├── signaling.ts        # rtc:signal 定向转发（v2 新增）
│   │   └── room-handlers.ts    # roster/进出场/outbox 推送/relay 降级
│   └── config.ts               # 环境变量 zod schema，进程内唯一配置入口
├── shared/
│   ├── events.ts               # Socket 事件/信令信封/handshake zod 类型
│   └── message.ts              # Message 与 roomId/peerId zod schema（HTTP/Socket/DC 共用）
├── scripts/
│   ├── export-openapi.ts       # 启动 buildApp()（不 listen）→ app.swagger() → openapi.json
│   └── orval.config.ts         # openapi.json → app/api 的 fetch 客户端
├── openapi.json                # 生成物，契约快照，进 git 便于 diff
├── react-router.config.ts      # framework mode 配置（ssr 开关等）
├── vite.config.ts              # reactRouter() + fastifyReactRouterDev()
└── package.json                # 唯一工作区（非 monorepo）
```

要点：
- `server/app.ts` 把「组装」和「监听」分开，`scripts/export-openapi.ts` 与集成测试都复用
  `buildApp()`，保证导出的 OpenAPI 与真实运行的路由**永远一致**。
- `app/api` 是生成目录：本地开发改了路由 schema 后需跑 `npm run codegen` 再引用新客户端。
- 旧的 `src/`、`typings/`、`gulpfile.js`、`ecosystem.config.js` 等在新结构验收后删除
  （见 08 迁移计划）。

## 4. 请求分流规则（一个端口如何服务三类流量）

| 请求 | 处理者 | 说明 |
|---|---|---|
| `GET /socket.io/*`、WebSocket upgrade | Socket.IO engine | 在 HTTP server 层拦截，不进入 Fastify 路由树 |
| `/api/*` | Fastify routes | zod 校验失败由 Fastify 直接返回 400（含 error 详情） |
| `GET /documentation*` | @fastify/swagger | OpenAPI UI，仅非生产环境注册 |
| 其余所有路径 | react-router-fastify catch-all | dev：Vite SSR；prod：`@fastify/static` 命中静态资源则直接返回，否则进 React Router 渲染/返回 SPA 入口 |

## 5. 与现状的结构性差异速览

| 维度 | 现状 | 目标 |
|---|---|---|
| HTTP 框架 | Koa 2 + ts-brpc 代码生成 | Fastify 5 + zod 声明式 |
| RPC/HTTP 边界 | 全是 POST 的 RPC 风格 `/api/<Service>/<method>` | REST 资源风格 `/api/rooms/:id/outbox` 等（见 03） |
| **消息数据面（v2）** | Socket.IO 中转 + Redis 全量存消息 | WebRTC DataChannel 端到端直传，服务器不留痕（10） |
| 前端路由 | react-router-dom 6 declarative | React Router 8 framework mode（routes.ts + 文件路由） |
| UI | antd-mobile 5 + less modules | HeroUI 3.2.6 + Tailwind v4（见 05） |
| API 客户端 | ts-brpc 生成的 `rpc.Room.join()` | orval 生成的 fetch 客户端 + 类型（见 03） |
| 实时事件类型 | `src/lib/interface.ts` | `shared/events.ts`（正名，见 04） |
| 静态托管 | koa-static + history fallback | 适配器内建 `@fastify/static`（见 07） |
| server 构建 | gulp + ts-brpc meta | 单一 `tsc`（或 tsx 直跑），无代码生成步骤 |
| 校验 | 手写 if + errorJSON | zod schema 自动校验 + 标准状态码 |
| 文档 | 无 | OpenAPI + Swagger UI 自动生成 |
