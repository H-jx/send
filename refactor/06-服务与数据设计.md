# 06 · 服务与数据设计（server/services）

业务层是定稿要求的汇合点：**房间 API 与 Socket.IO 共用同一套服务**，
`server/routes/*` 与 `server/realtime/*` 只做协议适配，不写业务。

## 1. 配置：`server/config.ts`

## 2. Redis：`server/services/redis.ts`

- `ioredis` 单例，`new Redis(env.REDIS_URL)`；`maxRetriesPerRequest: 3` 同现状。
- 不再做启动时 `get('foo')` 探测：Fastify `onReady` 打一条 `ping` 结果日志即可，
  `/api/health` 不依赖 Redis 成功（降级返回，见 03）。

## 3. 房间服务：`server/services/room.ts`（v2：注册/secret/回执）

> **v2 修订**：P2P 化后聊天消息不再进 Redis（原 LIST 方案与 `appendMessage/getMessages`
> 退役，仅当 relay 需要代收时再评估，默认不做——relay 也不落库，10 §1）。
> 同时修复 v1 文档自身缺陷：`room-meta-{id}` HASH 不设 TTL 会造成键泄漏——
> 改为**单键 HASH**，TTL 挂其上一处生效。

| 键 | 类型 | 内容 | TTL |
|---|---|---|---|
| `room-{id}` | HASH | `createdAt`、`secretHash`（SHA-256）、`lastSeenAt` | `ROOM_TTL_SECONDS`，每次有人握手/进房校验时 `EXPIRE` 续期（对齐旧「活跃续期」语义） |
| `room-outbox-{id}` | HASH | field=回执 id，value=JSON 元数据（name/size/sha256/key/expiresAt） | 同上；cleanup 另清已过 `expiresAt` 的 field |
| `invite-secret` 派生 | — | 只存哈希，明文仅 A1 响应一次（10 §11） | — |

## 4. 统计服务：`server/services/statistics.ts`

- 键与现状一致：`statistics-rooms`、`statistics-users`（SET）。
- `recordRoomKey(roomId)`：握手/A2 时调用（现状语义）。
- `recordUser(peerId)`：**恢复写入**（销 D9/D13），身份为握手 auth 里的 peerId（uuid），匿名默认不记。
- `listRooms()` / `listUsers()`：A5/A6。
- `removeRoomKey`：清扫时调用。

## 5. 清扫任务：`server/services/cleanup.ts`

取代现状「disconnect 时全量 fetchSockets + 遍历」（D7）：

- 定时器（`setInterval`，默认 10 分钟，env 可配；`fastify.addHook('onClose')` 清理）。
- 流程：`SMEMBERS statistics-rooms` → 房间注册键 `room-{id}` 已过期（EXISTS=0）**且
  socket adapter 内无该房间成员**（单进程直接查 `io.sockets.adapter.rooms`，不跨进程）
  → `removeRoom` + SREM；另外遍历 `room-outbox-*` 删除过期 field。
- 房间自然过期即消失（TTL 挂在注册键上），sweep 只是回收 `statistics-rooms` 的悬空成员，
  不再有「空消息房间」判定（消息已不在服务端，v2）。
- 只在单实例执行——部署仍是单进程（定稿），无需分布式锁；若未来上 PM2 cluster
  再引入 `INSTANCE_ID` 判断或 Redis `SETNX` 锁（备注于 07）。

## 6. MinIO 服务：`server/services/minio.ts`

```ts
signUpload({ roomId?, fileName, size }) → { method:'PUT', key, uploadUrl, downloadUrl, expiresAt }
signDownloadByKey({ roomId, key })      → { downloadUrl }   // v2：A4 `{key}` 形态，领取回执用
```

- `minio` SDK 客户端单例（配置见 §1）。
- Key 生成（D8）：`${roomId ?? uuidv4()}/${randomHex(8)}-${sanitizeName(fileName)}`；
  `sanitizeName` = `path.basename` + 去 `..`/分隔符/控制字符 + 限长 200。
- `presignedPutObject` + `presignedGetObject` 成对，`expires = UPLOAD_SIGN_TTL_SECONDS`。
- **v2 前缀约束**：`signDownloadByKey` 只接受以请求房间 `${roomId}/` 开头的 key，
  否则 403——回执文件不可跨房间领取。
- URL 规范化（D12）：按 `MINIO_URL_SCHEME` 处理签名 URL 协议：
  `keep`（原样）/ `protocol-relative`（剥协议，等值现状 `replace(/https?:/,'')`）/
  `https`（强制 https，要求 MinIO 侧 TLS 或反代）/ `auto`（跟随请求 proto，过渡默认，
  等价现状行为）。若配置了 `MINIO_PUBLIC_HOST`，替换 URL 主机部分。
- 秒传（D10，本期不实现）：预留 `checkExists(key)`（`statObject`），
  A4 未来加 `md5` 入参后走「存在则只回 downloadUrl」分支（现状被注释的逻辑回归）。

## 8. ICE 凭证服务：`server/services/ice.ts`（v2 新增）

- `buildIceConfig(roomId, peerId)`：返回 A8 响应体。
  STUN 静态；TURN 两条（`turn:HOST:443?transport=tcp` 与 `turns:HOST:5349`，
  443 优先，穿透运营商 UDP 封锁）。
- 临时凭证：`username = ${now+TTL}:${roomId}-${peerId}`，
  `credential = base64(HMAC-SHA1(TURN_SECRET, username))`（coturn REST auth 约定），
  TTL 默认 12h。username 内嵌房间与 peer → coturn 日志可直接审计与限额。
- 不做连接数硬控（coturn 侧 `total-quota/per-IP quota` 配置解决，见 07 §5）。
- 纯计算函数，无外部依赖，jest 表驱动测试（过期时间、HMAC 基线值）。
