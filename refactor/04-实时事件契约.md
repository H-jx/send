# 04 · 实时事件与 P2P 信令契约（修订版）

> **修订说明**：本文件原为"服务器中转消息"契约。按定稿变更（见 10），聊天数据面
> 改走 WebRTC DataChannel；Socket.IO 退居**信令、在线状态、房间注册、降级中继、
> 文件回执**。同 HTTP server 同端口的挂载方式不变（engine.io 先拦 `/socket.io/*`）。

## 1. Socket.IO 事件总表

| 事件 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `room:roster` | 服务端 → 新成员 | `{ peers: [{ socketId, peerId }], outboxHint: number }` | 原 `ROOM_JOINED`(历史) 退役：历史在本地 IndexedDB，这里只给"谁能连" |
| `room:peer-join` / `room:peer-leave` | 服务端 → 其余成员 | `{ socketId, peerId }` | 成员进出（mesh 建连触发器） |
| `rtc:signal` | **双向** | `{ to: socketId, from: socketId, data: RtcSignal }` | SDP offer/answer、ICE candidate 信封，服务器盲转不解析内容 |
| `outbox:new` | 服务端 → 全员 | `{ id, name, size, expiresAt }` | 对方离线时投递的文件回执（**只有元数据**，内容在 MinIO） |
| `msg:send` / `msg:receive` | 同原版 | `Message` + ack | **仅 relay 降级模式**使用；降级后**不再落库**（P2P 化改造点） |
| `room:evicted` | 服务端 → 自己 | `{ reason: 'duplicate-peer' }` | 同 peerId 顶号（同标签页刷新/多标签） |

旧事件映射：`ROOM_JOINED → room:roster +（本地历史）`；`MSG_SEND/MSG_RECEIVE` 保留但降级专用。

## 2. 握手与鉴权（`server/realtime/index.ts`）

```ts
// 客户端（不再用 query，改 socket.io v4 的 auth 字段）
io('/', {
  transports: ['websocket'],
  auth: { roomId, peerId, secret },   // secret 来自 URL fragment #s=
})
```

- 服务端中间件依次校验：`socketHandshakeSchema`（zod）→ 房间存在 →
  `secret` 哈希匹配（06 §3）→ 同 `peerId` 旧连接 `disconnect('duplicate-peer')` →
  `socket.join(roomId)` → 下发 `room:roster` → 广播 `room:peer-join`。
- 任一步失败 → 拒连（页面侧已被 A2 拦住，这里兜底）。
- `statistics.recordRoomKey/recordUser(peerId)` 在此处调用（销 D9/D13：身份统一为 peerId）。

## 3. `shared/events.ts`（契约唯一来源，修订版）

```ts
// shared/events.ts
import { z } from 'zod'
import { messageSchema, roomIdSchema } from './message'

export const SOCKET_EVENTS = {
  ROOM_ROSTER:    'room:roster',
  PEER_JOIN:      'room:peer-join',
  PEER_LEAVE:     'room:peer-leave',
  RTC_SIGNAL:     'rtc:signal',
  MSG_SEND:       'msg:send',      // relay 降级专用
  MSG_RECEIVE:    'msg:receive',   // relay 降级专用
  OUTBOX_NEW:     'outbox:new',
  ROOM_EVICTED:   'room:evicted',
} as const

export const peerIdSchema = z.string().uuid()

export const socketHandshakeSchema = z.object({
  roomId: roomIdSchema,
  peerId: peerIdSchema,
  secret: z.string().length(22),     // base64url(16B)
})

export const rtcSignalSchema = z.object({
  to: z.string(),
  data: z.discriminatedUnion('kind', [
    z.object({ kind: z.literal('sdp'), sdpType: z.enum(['offer', 'answer']), sdp: z.string() }),
    z.object({ kind: z.literal('candidate'), candidate: z.record(z.string(), z.string()) }),
  ]),
})

export const relayMessageSchema = messageSchema.extend({
  transport: z.literal('relay'),     // 客户端据此在 UI 标记「未加密直达」
  sendBy: z.string().uuid(),         // = peerId，服务器仍补 time
})

export type SendAck = { ok: true; id: string } | { ok: false; message: string }

export interface SocketServerToClient {
  'room:roster':    (r: { peers: { socketId: string; peerId: string }[]; outboxHint: number }) => void
  'room:peer-join': (p: { socketId: string; peerId: string }) => void
  'room:peer-leave':(p: { socketId: string; peerId: string }) => void
  'rtc:signal':     (f: z.infer<typeof rtcSignalSchema> & { from: string }) => void
  'msg:receive':    (m: z.infer<typeof relayMessageSchema>) => void
  'outbox:new':     (n: { id: string; name: string; size: number; expiresAt: string }) => void
  'room:evicted':   (r: { reason: string }) => void
}
export interface SocketClientToServer {
  'rtc:signal': (f: z.infer<typeof rtcSignalSchema>, ack?: (r: SendAck) => void) => void
  'msg:send':   (m: z.infer<typeof relayMessageSchema>, ack?: (r: SendAck) => void) => void
}
```

（WebRTC DataChannel 内的帧协议不属于 Socket 契约，定义在 10 §7。）

## 4. 服务端 handler（`server/realtime/`）

| 文件 | 职责 |
|---|---|
| `index.ts` | `io.Server(app.server, …)`：CORS/pingInterval 入 env、握手中间件、`room:evicted` |
| `signaling.ts` | `rtc:signal` 转发：`to` 必须在同房间且在线，否则 ack 失败；服务器不解释 SDP/candidate 内容 |
| `room-handlers.ts` | roster/进出场广播、outbox 新回执推送、relay 降级的 `msg:send`（校验→补 time/transport→`socket.to(room)` 广播→ack；**不落 Redis**） |

与房间 API 的共用关系不变：注册、secret、outbox 全在 `server/services/room.ts`，
routes 与 realtime 同一出口（原定稿要求）。

## 5. 断线行为

- `socket.leave` + 广播 `room:peer-leave`（客户端拆对应 RTCPeerConnection）。
- 现状「disconnect 时全量 fetchSockets 清扫」仍移除（D7），改由 `services/cleanup`
  定时任务：注册记录靠 TTL 自然过期；`statistics-rooms` 对「无在线成员且注册已过期」
  的键做回收（判定方式见 10 §10）。

## 6. WebRTC 信令之外（范围声明）

本期只做 **DataChannel**（文本/文件）。音频视频通话所需的媒体轨道、SFU、
带宽评估不在本方案内——信令信封 `rtc:signal.data` 预留 `kind:'sdp'` 的
`media` 扩展位即可，届时不改传输层。
